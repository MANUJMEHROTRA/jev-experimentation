Typed decision models · October 2026

Decisions,
not text.

TypeSafe's Jev and Convai's open-source Laya answer typed questions about a piece of text with a probability distribution, in a single encoder pass. They generate no tokens, so there is no JSON to parse and no free-text answer to go off-schema.

This page takes the mechanism apart: how a request becomes one sequence with a [MASK] per option, how RLCD trains honest probabilities, and what our own reproduction learned on the same benchmark.

The landscape

    
Two System 1 models, one interface

    
Both models take a state (a string, JSON object, or list of turns) and named questions of three types. choice picks among caller-defined options. score rates on an ordered rubric. noul gives the probability a statement is true. Jev is a hosted API with undisclosed internals. Laya publishes weights, code and its training notebook under Apache-2.0, which is why the rest of this page builds on Laya's design.

Why one pass is fast

      
An LLM writes its answer. A System 1 model reads it off.

      
To return three typed answers, a decoder LLM generates the JSON one token at a time. Each token is a full forward pass that depends on the previous one, and the result still has to be parsed and validated against the schema.

      
A System 1 model puts every allowed answer into the input. One bidirectional encoder pass scores them all at once, and questions about the same state are batched together. The output is already typed, so there is nothing to parse.

      
The animation is schematic: one block per forward pass, not a timing measurement.

Training signal

    
RLCD: rewarding honest probabilities

    
Reinforcement learning for calibrated decisions treats the logits as the mean of a Gaussian policy. Each step samples a group of noisy logit vectors, turns each into a reported distribution, and scores it with a strictly proper scoring rule against the observed outcome. The rule's expected reward is highest only when the report equals the true outcome distribution. Samples that beat their group's average are reinforced. This playground uses the same estimator as rlcd_loss in this repo: zero-mean noise, a group of 4, a normalised group-mean advantage.

After training

      
One temperature per question type

      
Raw decision models are usually overconfident. Laya reports an expected calibration error (ECE) of 0.213 before scaling and 0.081 after. The fix is one scalar per question type: divide the logits by T before the softmax. A value of T above 1 softens every answer. The argmax never changes, so accuracy is untouched.

      
Fit T on held-out cases that never entered training. On training items the model is already near-certain and near-correct, so a temperature fitted there measures fit, not calibration.

      
The data here is a simulated overconfident model: 2,000 four-option questions whose logits are 2.2× too sharp. Our real run's reliability diagrams are in the next section.

Build one yourself

Use a trained model


from transformers import AutoTokenizer
from jev_experimentation import DecisionAgent, MarkerDecisionModel

path = "outputs/ModernBERT-base/model"
model = MarkerDecisionModel.load_pretrained(path)
tokenizer = AutoTokenizer.from_pretrained(f"{path}/tokenizer")
agent = DecisionAgent(model, tokenizer)

result = agent.predict(
    {"body": "We were billed twice for March. Refund it today."},
    {
        "department": {"type": "choice",
                       "instructions": "Which team should handle this?",
                       "criteria": {"billing": "invoices, refunds",
                                    "technical": "bugs, outages"}},
        "urgency": {"type": "score", "instructions": "How urgent?",
                    "criteria": ["not urgent", "soon", "blocking"]},
        "refund": {"type": "noul",
                   "instructions": "The customer asks for a refund."},
    },
)
result["answers"]["department"]["choice"]   # e.g. "billing"
result["answers"]["refund"]["noul"]          # P(true)
